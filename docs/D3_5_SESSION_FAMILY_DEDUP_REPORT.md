# D3.5 Session-Level Question Family Deduplication Report

**Date**: 2026-09-17  
**Status**: COMPLETE  
**Verification**: 236 tests pass, typecheck clean, production build pass

---

## Problem

Content bank contains **295 duplicate groups** (836 questions) across 462 unique families. Without session-level deduplication, a user could see 2–5 nearly identical questions in the same practice session, wasting time and degrading learning value.

## Solution

Family-aware session selection: at most **one question per family** enters any session. Families are consumed on **presentation** (not on answer submission), so skipped/interrupted sessions still prevent reuse.

## Architecture

```
content-family-map.json (462 families)
    ↓
getFamilyId(qid) → familyId
    ↓
sample() filters by family → selected[]
    ↓
build() validates with assertUniqueQuestionFamilies()
    ↓
LearningSession (guaranteed unique families)
```

### Data Flow

1. **Family Map** (static): QID → familyId lookup
2. **`sample()`** (runtime): Dedup during selection, first-seen family wins
3. **`canAddToSession()`** (runtime): Cross-call dedup for builders that call `sample()` multiple times
4. **`assertUniqueQuestionFamilies()`** (defensive): Catch any invariant violations before session creation
